## 判断

本轮只观察到 train 编辑奖励与有效补丁数量增加，没有严格成功或可执行测试改善；
regression 的补丁形成表现反而下降。样本很小，不能把这些差异宣称为统计显著的提升或退化。
按照运行前的判断标准，**不继续扩大旧奖励下的多步 GRPO**，不消耗 held-out 做选择。

奖励上涨不等于修复能力改善：旧规则给“有效补丁 + 主动测试”0.15，新增测试失败也可以得分。
此次 3 条这样的样本（SFT 1、GRPO 2）说明需要修正这个激励。

## 可选奖励 conservative-v2

已在本地实现、经过测试，尚未部署到远程 worker，也尚未执行任何新训练。
worker 显式使用 `--reward-version conservative-v2` 启用，默认仍是 `legacy-v1`，
以免恢复旧实验时悄悄切换目标。新 audit 的 reward components 会记录版本。

- 安全违规为 -1；严格成功保持为 1，评测成功定义不变。
- 超时、未知结果、无补丁、无效补丁、没有修改后主动验证、出现新增失败，都不给部分奖励。
- 部分奖励要求基线与最终 verifier 均为可比较的 pytest 失败结果，有失败测试标识，
  exit code 均为 1；检测到 collection error 或 error summary 时拒绝部分奖励。
- 有效且无新增失败、但没有减少失败的补丁只得 0.03。
- 在上述条件下减少失败，另加 `0.25 × 减少比例 + 0.10`。

0.03 是待验证的设计选择，不是已证明有效的超参数。这个版本堵住了当前已知的奖励漏洞，
不代表模型已获得更强的语义修复能力。下一阶段先在 train 找到偶尔能减少真实失败测试的任务，
保存完整轨迹与 verifier 输出，再用独立新运行验证奖励和组内差异；不能仅凭编辑奖励继续扩步。
旧 audit 缺少完整测试输出，不能把它们重打分后冒充一次 conservative-v2 在线训练结果。

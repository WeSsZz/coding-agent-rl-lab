## Notes that matter more than the versions

1. veRL v0.9.1 manages several virtual environments from a single pyproject using `uv` "conflicts
   forks", so different backends can hold different torch builds. Install through veRL's own
   mechanism (`uv sync --extra fsdp --extra vllm`) rather than by hand, or the forks are lost.

2. The stack is **cu130**. That is a hard prerequisite on the rental box: the NVIDIA driver must
   support CUDA 13. If it does not, the options are to update the driver or to move off this
   veRL tag, and that decision must be made *after* reading `nvidia-smi`, not before.

3. Route v1's environment is not reproducible and must not be reused as a base: its
   `pyproject.toml` declared no dependencies at all, torch and peft came from the base image via
   `--system-site-packages`, and a `peft` 0.21.0 overlay at `/root/autodl-tmp` was required but
   never recorded. This file exists so that failure is not repeated.

4. `scripts/grpo_sitecustomize.py` in route v1 hides the `vllm` package from the training
   interpreter. That shim must **not** be installed into this environment: route v2 requires vLLM.
